Vocat — это веб-панель управления с открытым исходным кодом и набор инженерных инструментов для сотовых модемов Quectel класса EC20/EC25 и China Mobile серии ML307. Она объединяет в одном автономном сервисе обнаружение модемов, состояние радиосвязи в реальном времени, терминалы AT и USSD, SMS, WiFi Calling, управление eSIM, выбор сети, маршрутизацию через прокси, уведомления, журналы аудита и автоматизацию релизов.

Бэкенд написан на Go, интерфейс построен на React и TypeScript, а производственный фронтенд встроен в бинарный файл Go. Один исполняемый файл содержит веб-приложение и использует SQLite для постоянного хранения состояния.

## Поддерживаемое оборудование

Vocat ориентирован на модули Quectel на базе Qualcomm и модули China Mobile серии ML307, которые предоставляют совместимые интерфейсы AT, QMI, последовательный порт и USB-сеть, включая:

- Quectel EC20
- Quectel EC25
- Семейство Quectel EG25
- Совместимые модули EG600 и родственные
- Серия China Mobile ML307 (например, ML307A-E5, различные OEM-варианты)

Доступные функции зависят от прошивки модуля, конфигурации USB, возможностей SIM/eSIM, драйверов хоста, радиосети и настроек оператора.

## Установка

### Установка в Linux одной командой

От имени root (включая OpenWrt/Kwrt, где `sudo` обычно отсутствует):

```bash
curl -fsSL https://raw.githubusercontent.com/MengMengCode/VoCat/master/scripts/install.sh | bash
```

Обычным пользователем в дистрибутиве с sudo:

```bash
curl -fsSL https://raw.githubusercontent.com/MengMengCode/VoCat/master/scripts/install.sh | sudo bash
```

Проверить предварительные требования к VoWiFi/XFRM на хосте без установки VoCat:

```bash
curl -fsSL https://raw.githubusercontent.com/MengMengCode/VoCat/master/scripts/install.sh | bash -s -- --check-env
```

Установить конкретную версию:

```bash
curl -fsSL https://raw.githubusercontent.com/MengMengCode/VoCat/master/scripts/install.sh -o install.sh
sudo bash install.sh 0.0.2
```

Для VoWiFi IMS требуется Linux XFRM/IPsec. В OpenWrt/Kwrt установщик пытается установить из собственного репозитория прошивки точно соответствующие пакеты `ip-full`, `kmod-ipsec`, `kmod-ipsec4/6`, `kmod-crypto-authenc`, AES-CBC и SHA1. Если подходящие модули ядра недоступны, используйте прошивку, которая их содержит; ни в коем случае не устанавливайте принудительно модули kmod, собранные для другого ядра.

Если ваше ядро не поддерживает XFRM/IPsec и вам нужны только функции без VoWiFi (например, сотовые SMS или передача данных), установите с параметром `--skip-vowifi-check`:

```bash
curl -fsSL https://raw.githubusercontent.com/MengMengCode/VoCat/master/scripts/install.sh -o install.sh
sudo bash install.sh --skip-vowifi-check
```

Установщик:

- определяет архитектуру `amd64`, `386`, `arm64`, `aarch64` или `armv7`;
- загружает соответствующий бинарный файл из GitHub Releases;
- проверяет его по файлу `SHA256SUMS`;
- устанавливает Vocat в каталог `/opt/vocat`;
- создаёт защищённый сервис systemd с правами доступа к оборудованию и сети, необходимыми для работы Vocat;
- сохраняет конфигурацию времени выполнения в `/etc/vocat/env`;
- генерирует случайный начальный пароль администратора при первой установке.

После установки откройте в браузере:

```text
http://<server-address>:7575
```

### Ручная установка бинарного файла

Загрузите нужный бинарный файл и `SHA256SUMS` из GitHub Releases:

| Платформа | Файл релиза |
| --- | --- |
| Linux x86-64 | `vocat-linux-amd64` |
| Linux x86 32-bit | `vocat-linux-386` |
| Linux ARM64 | `vocat-linux-arm64` |
| Linux AArch64 | `vocat-linux-aarch64` |
| Linux ARMv7 | `vocat-linux-armv7` |

Проверьте и установите:

```bash
sha256sum -c SHA256SUMS --ignore-missing
sudo install -d -m 0755 /opt/vocat/bin /opt/vocat/data
sudo install -m 0755 vocat-linux-amd64 /opt/vocat/bin/vocat
read -rsp "Admin password: " VOCAT_BOOTSTRAP_PASSWORD; echo
printf '%s\n' "$VOCAT_BOOTSTRAP_PASSWORD" | sudo /opt/vocat/bin/vocat bootstrap-admin
unset VOCAT_BOOTSTRAP_PASSWORD
sudo env \
  VOCAT_DATABASE_PATH=/opt/vocat/data/vocat.db \
  /opt/vocat/bin/vocat serve
```

Эта ручная команда запускает Vocat на переднем плане. Используйте команду `vocat serve`, чтобы процесс сразу запустил сервер; запуск `vocat` без аргументов от имени root в TTY вместо этого открывает интерактивное меню управления. Используйте установку одной командой, когда требуется управляемый сервис systemd и автоматический перезапуск.

### Docker

Для хоста Linux, который должен обнаруживать каждый подключённый поддерживаемый модем Quectel и продолжать видеть события горячего подключения USB, запустите Vocat в режиме доступа к оборудованию:

```bash
docker pull ghcr.io/mengmengcode/vocat:latest

read -rsp "Admin password: " VOCAT_BOOTSTRAP_PASSWORD; echo
printf '%s\n' "$VOCAT_BOOTSTRAP_PASSWORD" | docker run --rm -i \
  --user 0:0 \
  -v vocat-data:/opt/vocat/data \
  --entrypoint /opt/vocat/bin/vocat \
  ghcr.io/mengmengcode/vocat:latest bootstrap-admin
unset VOCAT_BOOTSTRAP_PASSWORD

docker run -d \
  --name vocat \
  --restart unless-stopped \
  --network host \
  --privileged \
  --user 0:0 \
  -v vocat-data:/opt/vocat/data \
  -v /dev:/dev \
  -v /sys:/sys:ro \
  ghcr.io/mengmengcode/vocat:latest
```

После запуска контейнера откройте `http://<server-address>:7575`. Сеть хоста необходима, чтобы сетевые интерфейсы QMI оставались видимыми для Vocat, а привилегированный доступ к устройствам — для последовательных портов, узлов управления QMI, интерфейсов TUN, настройки сети и устройств, добавленных после запуска контейнера. Привязка `/dev` делает новые узлы `ttyUSB*`, `ttyACM*`, `cdc-wdm*` и MHI `wwan*` видимыми без пересоздания контейнера.

Этот режим намеренно предоставляет Vocat широкий доступ к устройствам и сетевому стеку хоста. Используйте его только на доверенном хосте Linux. Автоматическое обнаружение распознаёт поддерживаемые USB-модемы Quectel (идентификатор производителя USB `2c7c`), модули China Mobile серии ML307 по строке продукта, а также модемы PCIe/MHI, представленные через подсистему Linux WWAN; произвольные конфигурации модемов не распознаются. Проброс только отдельных узлов с помощью `--device`, например `/dev/ttyUSB2`, `/dev/cdc-wdm0` или `/dev/wwan0qmi0`, ограничивает контейнер этими фиксированными узлами и не обеспечивает полноценного обнаружения нескольких устройств или горячего подключения.

На хостах OpenWrt цепочка input fw4 отбрасывает новые подключения от интерфейсов, которыми она не управляет, включая создаваемый Vocat интерфейс TUN для каждого сеанса VoWiFi. Поэтому Vocat вставляет узкие разрешающие правила `vocat-ims-*` (от P-CSCF к согласованному внутреннему адресу) с помощью `nft`, входящего в образ. Без них регистрация IMS и исходящие SMS работают, но входящие SMS и вызовы отклоняются. Если встроенный `nft` не может прочитать набор правил хоста, Vocat регистрирует сообщение `nft could not inspect the OpenWrt fw4 input chain`; в этом случае укажите в `VOCAT_NFT` собственный nft хоста:

```bash
cat > /opt/vocat-host-nft <<'EOF'
#!/bin/sh
exec /host/lib/ld-musl-$(uname -m).so.1 --library-path /host/usr/lib:/host/lib /host/usr/sbin/nft "$@"
EOF
chmod 755 /opt/vocat-host-nft
# Добавьте в приведённую выше команду docker run:
#   -v /usr:/host/usr:ro -v /lib:/host/lib:ro \
#   -v /opt/vocat-host-nft:/usr/local/bin/host-nft:ro \
#   -e VOCAT_NFT=/usr/local/bin/host-nft
```

Образ GHCR публикуется для `linux/amd64` и `linux/arm64`.

> [!TIP]
> **Примечание по развёртыванию на NAS / QNAP Container Station**:
> В операционных системах NAS, таких как QNAP QTS / QuTS hero (Container Station), пользовательские учётные записи администратора без прав root и механизмы изоляции томов могут приводить к тому, что именованные тома Docker (например, `-v vocat-data:/opt/vocat/data`) указывают на разные изолированные пути при однократной инициализации `bootstrap-admin` и в контейнере фоновой службы, вызывая ошибки «Неверный пароль» при входе через веб-интерфейс.
> В средах NAS настоятельно рекомендуется заменить именованные тома привязкой абсолютного пути хоста (например, `-v /share/Container/vocat/data:/opt/vocat/data` на QNAP) как при инициализации, так и при работе службы, чтобы обеспечить согласованное постоянное хранение базы данных SQLite.

### USB-считыватели SIM-карт

USB-считыватели SIM-карт используют службу Linux PC/SC. При наличии поддерживаемого менеджера пакетов установщик одной командой автоматически устанавливает и запускает `pcscd`, а также устанавливает драйвер CCID. В Debian/Ubuntu эквивалентная команда ручной установки — `apt install pcscd libccid`. Если USB обнаруживает считыватель CCID, но PC/SC недоступна, VoCat оставляет считыватель видимым в диалоге добавления устройства и сообщает об отсутствующей службе или драйвере, а не скрывает его без объяснения.

### Утилиты командной строки QMI

VoCat использует `qmicli` для проверки готовности канала управления QMI и `qmi-proxy` для мультиплексирования доступа к нему. Сеансами пакетной передачи данных управляет встроенный клиент QMI WDS, а не файлы состояния CID/PDH утилиты `qmi-network`. Установщик одной командой устанавливает и проверяет соответствующие утилиты. При ручном развёртывании в Debian/Ubuntu используется `apt install libqmi-utils`, в Arch Linux — `pacman -S libqmi`, в Alpine — `apk add qmi-utils`, а в OpenWrt — `opkg install qmi-utils`.

`vocat doctor --repair-dji-qmi` проверяет наличие `qmicli` перед изменением любой привязки USB-драйвера или активацией сигнала DTR. Если утилита недоступна, команда останавливается с подсказкой по установке и оставляет текущее состояние устройства без изменений.

### Хостовые сотовые данные по AT

Передача данных ECM/RNDIS на основе AT требует Linux, iproute2 и BusyBox с `udhcpc`.
VoCat должен монопольно управлять сетевым интерфейсом модема; отключите конкурирующие клиенты DHCP или профили NetworkManager для этого интерфейса. VoCat поддерживает аренду IPv4 и маркированные маршруты политик, не изменяя системный маршрут по умолчанию и настройки DNS-распознавателя. Для этого пути в настоящее время требуется услуга с поддержкой IPv4.

## Конфигурация

Vocat читает необязательный JSON-файл конфигурации из `VOCAT_CONFIG`, затем применяет переменные окружения `VOCAT_*`. Переменные окружения имеют приоритет.

| Переменная окружения | По умолчанию | Описание |
| --- | --- | --- |
| `VOCAT_ADDR` | `0.0.0.0:7575` | Адрес прослушивания HTTP. |
| `VOCAT_DATABASE_PATH` | `./data/vocat.db` | Путь к базе данных SQLite. |
| `VOCAT_SESSION_TTL` | `24h` | Время жизни сессии аутентификации. |
| `VOCAT_SECURE_COOKIES` | `false` | Помечает cookie сессии как безопасные при использовании HTTPS. |
| `VOCAT_SHUTDOWN_TIMEOUT` | `10s` | Тайм-аут корректного завершения работы. |
| `VOCAT_MAX_REQUEST_BODY_BYTES` | `1048576` | Максимальный размер тела запроса API. |
| `VOCAT_MCP_ENABLED` | `true` | Предоставлять конечную точку MCP по адресу `/mcp` для ИИ-агентов. Установите `false` для отключения. |
| `VOCAT_PROBE_UNKNOWN_USB` | `false` | Включить опрос неопознанных последовательных USB-устройств AT-командами. Опрос изменяет настройки порта и очищает входной буфер; включайте только тогда, когда эти порты выделены для модемов. Проверенные идентификаторы модемов определяются автоматически. Ключ JSON: `probe_unknown_usb`. |
| `VOCAT_REPO` | `MengMengCode/VoCat` | Доверенный репозиторий GitHub, используемый самообновлятором, в формате `owner/name`. |
| `GITHUB_TOKEN` | пусто | Необязательный токен GitHub для приватных репозиториев или более высоких лимитов API. |

Предоставленные пользователем пакеты настроек операторов Apple можно преобразовать командой `vocat carrier import-ipcc` в профили операторов, доступные для проверки и ограниченные списком разрешённых элементов; см. [docs/CARRIER_IPCC_IMPORT.md](CARRIER_IPCC_IMPORT.md).

Учётные данные администратора хранятся только в SQLite. Один раз инициализируйте пустую базу данных командой `vocat bootstrap-admin`; переменные окружения и конфигурация JSON не могут задать или перезаписать имя пользователя либо пароль администратора.

Не храните токены Telegram, пароли SMTP, секреты вебхуков, учётные данные SIM или другие приватные данные в репозитории. Настраивайте их через параметры приложения или защищённые файлы окружения.

## Единый вход (SSO)

VoCat поддерживает Pocket ID через OpenID Connect, приложения OAuth на GitHub.com и универсальные поставщики Generic OAuth2. Выберите одного поставщика в разделе **Настройки → Единый вход (SSO)**. По умолчанию SSO отключён, а вход по паролю остаётся доступным. Сначала войдите под локальным администратором, сохраните поставщика и явно привяжите внешнюю учётную запись перед включением SSO. Другие внешние учётные записи не могут регистрироваться или становиться администраторами, включая учётные записи с тем же адресом электронной почты, что и у привязанной.

### Pocket ID

1. Используйте для VoCat HTTPS-источник, например `https://vocat.example.com`, и установите `VOCAT_SECURE_COOKIES=true`. В настройках SSO выберите **Pocket ID**. В поле публичного источника изначально подставляется текущий адрес браузера; при необходимости отредактируйте поле **Публичный адрес VoCat**. Компактный URL-адрес обратного вызова и кнопка копирования отображаются сразу, поэтому URL можно скопировать до создания клиента OIDC или сохранения каких-либо учётных данных: `https://vocat.example.com/api/auth/sso/callback`.
2. В Pocket ID создайте отдельный конфиденциальный (**Confidential**) OIDC-клиент для VoCat. Зарегистрируйте точный URL обратного вызова и убедитесь, что целевой пользователь или группа имеют право использовать этот клиент. Для VoCat и Komari требуются отдельные клиенты и локальные сессии.
3. В VoCat введите точный публичный `APP_URL` Pocket ID в качестве Issuer, а также введите Client ID и Client Secret, выпущенные для клиента, созданного на шаге 2. Поле Client ID содержит подсказку, где найти это значение. Области видимости (Scopes) и PKCE S256 обрабатываются VoCat автоматически. Аутентификация клиента для токена выбирается из проверенных метаданных Discovery с приоритетом `client_secret_basic` перед `client_secret_post`. Сохраните настройки, пока SSO остаётся отключённым. Изменение адреса сразу обновляет отображаемый URL обратного вызова; эти изменения вступают в силу для авторизации после сохранения.
4. Проверьте сохранённую конфигурацию; при успешной проверке отображается сообщение **Проверка конфигурации пройдена**. Затем привяжите учётную запись. Выполните вход через Passkey в Pocket ID, предоставьте согласие и подтвердите возвращённую привязку в VoCat. Проверка конфигурации валидирует только метаданные и доступность сети; она не может проверить секрет клиента или авторизацию пользователя без фактического входа.
5. Включите SSO и сохраните. Используйте окно инкогнито для проверки входа через SSO, возврата на запрошенную страницу и первого запроса, изменяющего состояние.

На странице настроек отображается привязанная учётная запись и действие отвязки. Чтобы сменить внешнюю учётную запись, сначала отвяжите её, затем привяжите нужную учётную запись и снова включите SSO.

Issuer сопоставляется строго точно, включая путь и завершающий слэш. Вход в Pocket ID использует проверенные `issuer + sub` из ID Token; эндпоинт UserInfo или утверждение email не требуются. Эндпоинты Discovery, авторизации, Token и JWKS должны использовать тот же origin, что и настроенный Issuer. Развёртывания с использованием `INTERNAL_APP_URL` с другим внутренним origin в этом выпуске не поддерживаются. Оставляйте публичный `APP_URL` в качестве Issuer. Ранее явно настроенные методы аутентификации и scopes сохраняются при обновлении настроек.

### GitHub и Generic OAuth2

Для GitHub создайте OAuth App на GitHub.com с точно таким же URL обратного вызова, выберите **GitHub**, введите его Client ID и Secret и выполните описанную выше последовательность: сохранение, проверка, привязка, включение. Конечные точки фиксированы для GitHub.com; областью действия по умолчанию является `read:user`, и требуется PKCE S256. Привязка осуществляется по стабильному числовому идентификатору учётной записи GitHub, поэтому смена логина не изменяет привязку. Поддержка GitHub Enterprise выходит за рамки этого релиза.

Для Generic OAuth2 в дополнение к учетным данным клиента укажите URL авторизации, Token и UserInfo. При выборе Generic OAuth2 отображаются scopes, имя поля ID пользователя верхнего уровня (по умолчанию `id`), параметры аутентификации токена и совместимости с PKCE. UserInfo запрашивается с токеном доступа Bearer. Идентификатор должен быть непустой строкой или целым числом; большие целочисленные ID сохраняют свое точное значение. Аутентификация токена по умолчанию — `client_secret_post`, а PKCE — S256. Отключайте PKCE только для поставщиков, у которых отсутствует поддержка PKCE. Generic OAuth2 не выполняет проверку ID Token OIDC.

### Сеть, учётные данные и сессии

Существующая политика сети источника VoCat также применяется к маршрутам SSO. Настройка SSO не делает установку общедоступной в интернете. Браузер должен иметь доступ к VoCat и конечной точке авторизации; процесс VoCat должен иметь доступ к конечным точкам Discovery, Token и JWKS/UserInfo с доверенными сертификатами TLS. Сохранение точного URL-адреса HTTPS Issuer Pocket ID или Generic утверждает эти адреса для подключений HTTPS, включая частные адреса RFC1918/IPv6 ULA. Фиксированные конечные точки GitHub остаются ограниченными общедоступными адресами.

Для внутренней службы HTTP Generic-поставщика явно укажите ее полный URL HTTP в поле Token/UserInfo. Каждый кандидат DNS и фактическое подключение для этих HTTP-назначений должны быть разрешенным частным адресом. Discovery Pocket ID не может утвердить другой origin; его конечные точки должны использовать origin настроенного Issuer. Сам Issuer, URL загрузки Discovery и конечная точка авторизации браузера всегда требуют HTTPS. Loopback, link-local, метаданные облака и другие адреса специального назначения остаются заблокированными для соединений с IdP. Установите частные сертификаты CA в доверенное хранилище хоста/контейнера; возможность обхода проверки TLS отсутствует. Использование localhost или HTTPS-источника для доступа к VoCat в браузере не зависит от этих разрешений соединений с IdP.

Прилагаемое развёртывание Compose использует сеть хоста. Проверяйте DNS, маршрутизацию и доверие CA из самого контейнера; не полагайтесь на доступность имен служб мостовой сети. Обратные прокси должны сохранять настроенный публичный origin. VoCat не выводит URL-адреса обратного вызова из пересылаемых заголовков host. Требуется развёртывание в корневом пути. Для локальной разработки с Vite используйте один согласованный loopback-origin (например, `http://127.0.0.1:5173`) для публичного адреса и регистрации обратного вызова; исключения сетевого транспорта IdP допустимы только в тестовых фикстурах.

Файлы cookie сессии и CSRF сохраняют `SameSite=Strict`; кратковременные файлы cookie авторизации используют `SameSite=Lax` для обработки межсайтовых GET-обратных вызовов верхнего уровня. Сохранение любой конфигурации SSO (включая отключение или ротацию секрета) аннулирует все сессии SSO. Отвязка учётной записи аннулирует сессии SSO этой привязки. Сессии по паролю и API-токены сохраняются после этих действий. Смена пароля локального администратора аннулирует все сессии и API-токены, отменяет незавершённые авторизации и сохраняет внешнюю привязку. Пользовательский интерфейс запрашивает повторный вход, когда успешная операция аннулирует текущую сессию SSO.

Оставьте поле ввода секрета пустым, чтобы сохранить текущий секрет, или введите новый секрет для его замены. На странице настроек нет элемента для полной очистки сохранённого секрета. Изменение поставщика, Client ID, Issuer или эндпоинтов/поля ID Generic переключает пространство имён идентификации, требует ввода новых учётных данных и повторной привязки; существующие привязки требуют явного подтверждения сброса. Чтобы сменить привязанную учётную запись, сначала отвяжите её, а затем создайте новую привязку. Секреты клиентов хранятся только на сервере в защищённой базе данных SQLite; флаг конфиденциальности маскирует ответы API и не шифрует базу данных. Сторонние токены не сохраняются и не возвращаются в браузер.

Обычный выход завершает только текущую сессию VoCat. Отключение учётной записи в IdP или выход из Pocket ID не аннулирует немедленно существующую сессию VoCat; она истекает согласно `VOCAT_SESSION_TTL` или может быть аннулирована отключением SSO либо отвязкой в VoCat. Общедоступный эндпоинт возможностей — `GET /api/auth/providers`. API настроек SSO и привязки требуют сессии браузера и CSRF для записи; токены Bearer не могут управлять ими. Конфликты ревизий конфигурации возвращают `409 sso_config_changed`; изменение источников идентификации возвращает `409 sso_rebind_required`.

### Обновление и откат

SSO добавляет версию схемы SQLite 29. Обновление сохраняет существующего администратора, сессии, API-токены и данные устройств; SSO остаётся отключённым до настройки. Перед обновлением запишите дайджест старого бинарного файла или образа и создайте резервную копию конфигурации, CA и полного каталога постоянных данных при остановленном VoCat либо используйте API резервного копирования SQLite / команду `.backup` для получения согласованного снимка. Простое копирование работающего файла базы данных в режиме WAL не является надёжной резервной копией.

При возникновении проблем с поставщиком отключите SSO в новой версии, чтобы восстановить доступ по паролю и сохранить текущие рабочие данные. Для возврата к бинарному файлу со схемой 28 требуется остановить VoCat и восстановить соответствующий снимок данных и конфигурации до обновления. Простой откат образа контейнера или ручное понижение `PRAGMA user_version` не могут понизить версию базы данных. По возможности восстанавливайте данные в отдельный каталог/том и сохраняйте новую базу данных для анализа. Восстановление снимка приводит к потере сообщений и изменений задач, зафиксированных после создания резервной копии. Для Docker обновление выполняется получением нового образа и пересозданием контейнера.

Перед релизом в рабочей среде выполните реальное тестирование Passkey/политики доступа в Pocket ID и отработайте сценарии обновления и отката.

## API-токены и MCP

Клиенты, отличные от браузера, проходят аутентификацию для тех же эндпоинтов `/api/...` с помощью токена Bearer вместо сессионных cookie и механизма CSRF браузера:

```bash
vocat token create --read-only --ttl 720h ci-runner   # выводит токен один раз
curl -H "Authorization: Bearer vcat_..." http://127.0.0.1:7575/api/devices
```

`vocat token list` и `vocat token revoke <name>` управляют списком токенов. Токены действуют с правами администратора; токен с флагом `--read-only` может отправлять только запросы `GET` (одно документированное исключение: чтение цепочки SMS помечает её локально как прочитанную — правило гласит: «никаких изменений оборудования или сети»). Ротация пароля администратора аннулирует все токены. Создавайте токены после первого выполнения `bootstrap-admin`. Удалённым клиентам Bearer также требуется политика сетевого доступа, разрешающая их IP-адрес; режим по умолчанию `internal` обслуживает только частные сети.

По умолчанию (для отключения установите `VOCAT_MCP_ENABLED=false`) тот же сервис предоставляет конечную точку MCP (Model Context Protocol) для ИИ-агентов по адресу `http://<host>:7575/mcp` с использованием транспорта Streamable HTTP и аутентификации по токену Bearer. Инструменты охватывают состояние устройств, цепочки SMS и защищённую отправку, просмотр и переключение профилей eSIM, а также состояние и переподключение WiFi Calling; конфиденциальные операции (прямые AT-команды, загрузка/удаление eSIM, SIM PIN, выбор сети, обновление системы) не предоставляются, а вывод инструментов никогда не содержит IMSI, SIM PIN или коды активации. Токен только для чтения получает список инструментов без инструментов записи. Отправка SMS подчиняется той же политике заблокированных номеров и общему часовому лимиту, что и веб-интерфейс, и выполняется через сотовый AT-канал (маршрутизация с приоритетом IMS при включённом WiFi Calling остаётся на стороне веб-интерфейса, а сообщения, отправленные через MCP, пока не записываются в историю диалогов веб-интерфейса).

Пример конфигурации клиента (на примере Claude Code):

```json
{
  "mcpServers": {
    "vocat": {
      "type": "http",
      "url": "http://192.168.1.10:7575/mcp",
      "headers": { "Authorization": "Bearer vcat_..." }
    }
  }
}
```

Документ по архитектуре и дизайну см. в [docs/API_MCP_DEVELOPMENT_PLAN.md](API_MCP_DEVELOPMENT_PLAN.md).

## Telegram-бот

Когда уведомления Telegram включены и настроены Chat ID и Admin ID, бот поддерживает:

```text
/status [device]
/esim <device>
/switch <device> <iccid>
/wfc <device> <status|on|off|reconnect>
/sms <device> <number> <message>
/ussd <device> <code>
/ussd_reply <session> <input>
/ussd_cancel <session>
```

Переключение профилей и отправка SMS используют одноразовые кнопки подтверждения. Бот не предоставляет команды загрузки, удаления или переименования eSIM.

Веб-терминал и Telegram совместно используют маршрутизацию USSD. При включённом WiFi Calling запросы используют IMS/USSI и возвращают ошибку готовности до завершения регистрации в IMS без отката на сотовую команду AT+CUSD. При отключённом WiFi Calling запросы используют сотовый USSD. Ответы на пункты меню и отмена всегда привязаны к исходному устройству и диалогу. Ошибки отмены фиксируются и сохраняют сессию для повторной попытки; запрос с неопределённым результатом отправки никогда не отправляется повторно автоматически по другому каналу.

Обработка диалогов USSI соответствует [3GPP TS 24.390](https://www.etsi.org/deliver/etsi_ts/124300_124399/124390/18.00.00_60/ts_124390v180000p.pdf). Неудачный запрос BYE сохраняет запись об отмене, но дальнейший ввод меню блокируется сразу после начала отмены ([RFC 3261, раздел 15.1.1](https://www.rfc-editor.org/rfc/rfc3261.html#section-15.1.1)).

## Обновление

Проверить наличие более нового GitHub Release:

```bash
vocat update --check --repo MengMengCode/VoCat
```

Установить последний релиз:

```bash
sudo vocat update --repo MengMengCode/VoCat
```

Обновлятор загружает бинарный файл, соответствующий текущей архитектуре Linux, проверяет его с помощью опубликованного файла `SHA256SUMS`, атомарно заменяет исполняемый файл и перезапускает службу systemd `vocat`, если она доступна.

Для установок Docker:

```bash
docker pull ghcr.io/mengmengcode/vocat:latest
```

Пересоздайте контейнер после получения нового образа.

## Разработка

Требования:

- Go 1.25 или новее
- Node.js 20 или новее
- npm

Запустить сервер разработки фронтенда:

```bash
cd web
npm install
npm run dev
```

Собрать встроенный фронтенд и запустить бэкенд:

```bash
cd web
npm run build
cd ..
go run ./cmd/vocat
```

Запустить все тесты:

```bash
go test ./...
```

Собрать рабочий бинарный файл:

```bash
go build -trimpath -ldflags "-s -w" -o vocat ./cmd/vocat
```

## Ответственное использование

Операции с сотовыми модемами и eSIM могут влиять на обслуживание абонентов, сохранённые профили, сетевую регистрацию и состояние оборудования. Создавайте резервные копии, внимательно проверяйте разрушительные действия и используйте программное обеспечение только в законных средах, где вам разрешено эксплуатировать подключённое оборудование и сетевые ресурсы.

Vocat не обходит аутентификацию оператора, сетевую политику, аппаратную безопасность или требования доверия eSIM. Поддержка операции означает, что Vocat может запросить её у модема или eUICC; устройство, профиль, сеть или оператор всё равно могут её отклонить.
